Case Study / PROJ_01

Signals Trading Console

An async Python engine that watches Binance, Coinbase, and Kraken for cross-exchange, triangular, and futures-basis opportunities in real time — rendered live in a Qt dashboard, with a built-in paper-trading engine to test strategies before risking anything.

Project Overview

Signals is a modular trading engine built around a single async loop: a TradingEngine polls exchange adapters, feeds live order books into a set of pluggable strategies, and renders the results either as a full-screen Rich terminal dashboard or a native PyQt window — same engine, two front ends.

The core arbitrage strategy doesn't just diff top-of-book prices. It pulls real order-book depth from each exchange, computes a VWAP-weighted fill price for the configured notional size, and only then calculates the net spread — so the numbers on screen reflect what an order of that size would actually fill at, not an optimistic quote.

core/orderbook.py 
def vwap_price(levels: List[Tuple[float, float]], qty: float) -> Optional[float]:
    """Given [(price, qty)] levels, return average execution
    price to fill `qty`. Returns None if insufficient depth."""
    remain = qty
    notional = 0.0
    filled = 0.0
    for price, level_qty in levels:
        if remain <= 0:
            break
        take = min(remain, level_qty)
        notional += take * price
        filled += take
        remain -= take
    if remain > 0:
        return None
    return notional / filled

A separate triangular arbitrage scanner routes through single-venue pairs, and a futures-basis strategy compares spot marks against perpetual futures to surface basis trades. All three strategies share the same Strategy base class and StrategyContext, so adding a new venue or a new strategy doesn't touch the engine's core wiring.

A paper-trading engine runs alongside the live scan, opening and closing simulated positions off real market data — exit thresholds, blowout stops, and max hold times are all configurable — so a strategy's edge can be tracked over time before it's ever backed by real capital. A Binance WebSocket feed keeps spot and futures mark prices live between polls, with automatic fallback to REST if the socket drops.

Key Features

  • Cross-Exchange Arbitrage – Depth-aware VWAP pricing across three exchanges, not just top-of-book quotes.
  • Triangular Arbitrage – Single-venue routing scanner for multi-leg opportunities.
  • Futures Basis – Compares spot vs. perpetual marks to surface basis trades.
  • Paper Trading Engine – Simulated fills against live data with configurable exits, stops, and hold times.
  • Live Qt Dashboard – Native desktop window with portfolio snapshot and per-strategy panels.
  • Binance WebSocket Feed – Live spot + futures mark prices with automatic REST fallback.
  • Rich Terminal Fallback – Full-screen console dashboard sharing the same engine, no GUI dependency required.

Development Highlights

  • - Built a shared Strategy/StrategyContext interface so exchanges and strategies compose independently of the engine loop.
  • - Implemented order-book VWAP fill pricing instead of naive best-bid/best-ask spread math.
  • - Wrote a standalone paper-trading engine that consumes the same strategy output as the live dashboard.
  • - Added a Binance WebSocket feed for live mark prices, with graceful fallback to REST polling.
  • - Covered exchange adapters and the futures strategy with an async test suite.
