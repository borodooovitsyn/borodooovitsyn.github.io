Vault Escape

A top-down stealth game built with Java Swing: sneak past patrolling guards, chase-triggered dogs, and cameras to collect valuables before time runs out — with every entity type covered by its own JUnit test class.

Project Overview

Vault Escape casts you as a robber who has to collect every golden valuable in a vault and reach the exit before time runs out — while patrolling guards, roaming dogs with a chase radius, static cameras, and lasers stand in the way. Get spotted and time gets docked; get caught enough and it's game over.

Built with Java Swing and Maven, the codebase separates entities (player, enemies, rewards), tiles, panels, and utilities into their own packages, with a shared Entity/Enemy hierarchy so each enemy type only has to implement its own movement and attack behavior. A Generator<T> utility spawns and tracks rewards and enemies without duplicating placement logic per type.

Every core class — entities, tiles, panels, level generation, animation, timers — has a matching JUnit test class, 22 in total, checked on every build via mvn test. The project also ships Javadoc-style documentation on public methods throughout, not just where it was convenient.

Key Features

  • Patrol AI – Guards walk fixed paths and reverse direction on collision, with a cooldown to prevent jittering at walls.
  • Chase AI – Dogs wander until the player enters range, then actively pursue.
  • Detection Hazards – Static cameras and lasers punish careless routing without patrol logic of their own.
  • Reward System – Required golden valuables plus time-limited bonus diamonds spawned via a shared generator utility.
  • Full Test Coverage – 22 JUnit test classes covering entities, tiles, panels, and utilities.

Development Highlights

  • - Designed a shared Entity/Enemy class hierarchy so new enemy types only implement movement and attack behavior.
  • - Built a generic Generator<T> utility to spawn and track both enemies and rewards without duplicated logic.
  • - Wrote a JUnit test class for every core game class as part of the build, not after the fact.
  • - Documented public methods with Javadoc throughout the codebase.
