TextMeCash

A mobile-first messenger with a payments wallet built in — real-time chat, voice/video calls, and Signal-protocol end-to-end encryption, plus peer-to-peer payment requests backed by a proper double-entry ledger.

Project Overview

TextMeCash pairs a Flutter mobile client with a Django backend running over Django Channels for WebSocket messaging — 1-to-1 and group chat, typing indicators, read receipts, and presence, all live. Audio and video calls run over WebRTC, signaled through the same WebSocket connection, with DTLS-SRTP encrypting every call by default.

Direct chats are protected with an actual Signal-protocol-style implementation: X3DH key exchange over Curve25519, a Double Ratchet for per-message keys, and AES-256-GCM encryption — all implemented client-side in Flutter, with keys held in the iOS Keychain. The server only ever stores ciphertext; images, voice notes, video circles, and files sent in direct chats are encrypted before upload and decrypted on-device.

The payments side isn't a bolted-on balance counter — it's a double-entry ledger: every transaction writes matched debit and credit LedgerEntry rows, each transaction carries a caller-supplied idempotency key to survive retries safely, and completed transactions get an HMAC-SHA256 integrity hash so tampering is detectable after the fact. Payment requests support equal auto-splitting across a group, QR-code payments, and encrypted transaction memos using the same E2EE keys as chat.

class LedgerEntry(models.Model):
    class Direction(models.TextChoices):
        DEBIT = "debit", "Debit"     # money leaving the account
        CREDIT = "credit", "Credit"  # money entering the account

    transaction = models.ForeignKey(
        Transaction, on_delete=models.PROTECT, related_name="entries"
    )
    account = models.ForeignKey(
        WalletAccount, on_delete=models.PROTECT, related_name="entries"
    )
    amount = models.DecimalField(
        max_digits=12, decimal_places=2,
        validators=[MinValueValidator(Decimal("0.01"))],
    )
    direction = models.CharField(max_length=6, choices=Direction.choices)

The backend is organized into focused Django apps — users, chat, media, payments — with media proxied through S3-compatible storage (MinIO in dev) and background processing handled by Celery. The whole stack, including WebSocket consumers and the payments ledger, is covered by an automated Django test suite runnable without Docker via an in-memory channel layer.

Key Features

  • Real-Time Messaging – 1-to-1 and group chat over WebSocket, with typing indicators, read receipts, reactions, and edit/delete.
  • Audio & Video Calls – WebRTC calls signaled over the existing WebSocket connection, encrypted by default via DTLS-SRTP.
  • End-to-End Encryption – X3DH + Double Ratchet (Signal-protocol pattern) for direct-chat text, images, voice, video, and files.
  • Wallet & Payments – Double-entry ledger, deposits/withdrawals/transfers, payment requests with group auto-split, and QR payments.
  • Key Backup & Restore – Password-protected E2EE key backup using Argon2id + AES-256-GCM, with auto-restore on new device login.
  • Message Forwarding – Per-group and per-chat forward policies, with E2EE content re-encrypted for the target conversation.

Development Highlights

  • - Implemented the Signal-protocol Double Ratchet client-side in Dart, including per-message key derivation via HKDF-SHA256.
  • - Designed the payments ledger around matched debit/credit entries rather than a single mutable balance field, so every transaction is auditable.
  • - Added idempotency keys and an HMAC-SHA256 integrity hash to protect transactions against retries and tampering.
  • - Built a browser-based test UI so two simulated users can be driven side-by-side without two physical devices.
  • - Wrote an automated test suite covering WebSocket consumers and the payments ledger, runnable without Docker.
