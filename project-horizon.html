Case Study / PROJ_03

Horizon Expedition

3D multiplayer survival and exploration game built in Unity. Features include synchronized combat, trading, and networked player systems developed using Mirror and C#. Designed for scalability and cooperative gameplay.

Project Overview

Horizon Expedition is a 3D multiplayer exploration and combat game developed in Unity using Mirror Networking. The project focuses on player cooperation, synchronized interactions, and a dynamic world that responds in real-time to every player’s actions.

The core idea was to build a scalable multiplayer framework capable of supporting real-time player combat, shared world objects, and network-synced inventories. Each player controls a fully animated 3D character equipped with movement, combat, and interaction systems designed to work seamlessly over a network.

Every element — from stamina and health systems to inventory and merchant interfaces — was built with server authority in mind to ensure fairness and prevent desynchronization. Players can collect, equip, trade, and store items across sessions through a global inventory system.

The project’s architecture follows a modular component design, separating responsibilities between networking logic, UI management, and core gameplay. This makes it easy to extend with additional features some of which were already shipped: trading system and procedurally generated maps.

Developed collaboratively by a small team of designers and programmers, Horizon Expedition reflects a balance between technical precision and creative design. The project served as a foundation for exploring concepts like player synchronization, server-side validation, and network object spawning in modern Unity environments.

Key Features

  • Multiplayer Networking – Real-time player synchronization using Mirror with server-side control.
  • Combat System – Melee and ranged combat with animation triggers, hit detection, and cooldown logic.
  • Inventory & Merchant Systems – Dynamic item management with server-wide consistency.
  • Player Stats – Stamina, hunger, and thirst mechanics that affect movement and performance.
  • NPC AI – Basic and ranged enemies powered by behavior trees and pathfinding.
  • UI/UX Systems – Interactive menus, chest systems, and a responsive pause/inventory interface.
  • Voxel-Based World – Lightweight voxel maps built in MagicaVoxel and integrated with collision systems.

Development Highlights

  • - Implemented authoritative server mechanics to ensure consistent gameplay across clients.
  • - Created custom player prefabs with synchronized stats, animations, and interactions.
  • - Integrated dynamic inventory UI and merchant NPC trading using scriptable objects.
  • - Designed an extendable combat manager for future addition of abilities and ranged attacks.
  • - Managed version control through GitHub for collaborative workflow.
